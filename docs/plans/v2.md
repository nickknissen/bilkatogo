# v2 plan: Order Totals, Missing Items, Pickup Points and product search

Agreed in the design session on 2026-10-26. Vocabulary lives in `GLOSSARY.md`, hard-to-reverse decisions in `docs/adr/`.

## Scope

- Read-only, like v1. Adding to the Cart is the next spec and builds on Article Numbers and Stores from this one.
- Every feature lands in the library and the CLI. Home Assistant only gets Order Total and Missing Items.
- Out: MCP server, order history statistics, Pickup Slot availability, member prices and personal offers (`cpOffer`), category browsing, EAN lookup, price watch in Home Assistant, refunds (`returns[]`).

## Money

- All amounts are `Decimal` kroner, currency DKK, converted from Bilka's øre in one place.
- Breaking: `Order.ordered_price`, `Order.packed_price` and `OrderDetails.price` change from `int` øre to `Decimal` kroner. Released as `0.2.0`. Home Assistant drops its `/ 100`.

## Order Total

- Ordered Total from `OrderHistory.orderedPrice`, Order Total from `OrderHistory.packedPrice` / `OrderDetails.price`.
- Breakdown from `OrderDetails.stat`: Deposit (`deposit`), Service Fee (`packing`), Packaging (`packaging_price`), Delivery Fee (`delivery_price`), Discount (`promo` + `membership_offer_discount` + `personalized_offer_discount` + vouchers).
- Even a `Bestilt` Order has a `packedPrice` that differs from `orderedPrice`; treat it as Bilka's estimate, not as packed. Captured 2026-11-02 (`tests/fixtures/order_history_received.json`): 859.98 against 876.53 ordered, equal to that Order's `OrderDetails.price`.
- CLI `order` shows Ordered Total, Order Total and breakdown. HA: monetary sensor with Order Total, breakdown and difference from Ordered Total as attributes.

## Missing Items

- A Missing Item is an Order Line packed short without a Replacement Product, carrying the missing quantity. Inferred shape: non-empty `unavailable_reason`, `replacement` null, no `children`; `stat.oos` on the Order. No real capture yet, so the fixture is synthetic and the raw line is still logged.
- Sold Out stays an Order Status for an Order where nothing could be packed.
- CLI `order` lists them. HA: count sensor with a list attribute and a `bilkatogo_missing_item` event fired once per Missing Item (Order Number + Article Number kept in storage), same as Substitutions.

## Pickup Points and Stores

- `shop/v6/AvailableDeliveryAddresses?orderByZipcode=1`: every Pickup Point with name, address and Store id (`sid`). Standalone points (e.g. Pickup Fredericia, `facility: 5`) are served by a Store.
- The customer's chosen Pickup Point comes from `shop/v6/Cart?extra=deliveryAddress,deliveryDate` (`deliveryAddress.sid`).
- CLI `bilkatogo pickup-points`.

## Product search (ADR 0004)

- Algolia app `F9VBJLR1BK`, index `prod_BILKATOGO_PRODUCTS`, public search-only key, hardcoded like `GIGYA_API_KEY`. Filter `isInAssortmentIn:<sid> AND nonsearchable:false`.
- Store: the named Pickup Point's Store, otherwise the one in the customer's Cart. So the client still requires an email and a search may log in.
- Returns Products: name, brand, Article Number, Price, Unit Price, in stock at the Store, and an Offer (Offer Price, label, end date, limit per customer) and Multibuy Offer text when present, all from `storeData[<sid>]`.
- CLI `bilkatogo search <text> [--pickup-point NAME] [--limit N] [--json]`.

## Unverified assumptions

- Shape of a Missing Item and of `stat.oos`.
- That a logged-in Cart returns `deliveryAddress` like the anonymous one.
- That `storeData` prices can differ between Stores (they were equal in the capture).
- `packedPrice` of a Cancelled or Sold Out Order (may be 0).
